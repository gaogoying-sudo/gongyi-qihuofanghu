# 整体方案设计架构

## 总目标

把菜谱从“人录进去的一组动作指令”，升级为“可校验、可复刻、可监控、可拦截、可回溯的安全工艺包”。

## 七层架构

1. 云端标准菜谱层
2. 客户本地化菜谱层
3. 单机执行工艺包层
4. 设备状态与健康参数层
5. 执行过程数据层
6. 安全规则与风险判断层
7. 测试验证与反馈回流层

## 核心判断

云端标准菜谱不能直接等于设备执行菜谱。同一条菜谱下发到不同机器后，必须结合设备型号、锅型、机芯、红外、锅黑、维护状态和健康参数展开成本机执行工艺包。

## 后续开发指向

- 标准菜谱与机器执行菜谱要分层管理。
- 机器上下文参数必须进入菜谱执行判断。
- 风险规则要支持录菜、生产、下发、后台扫描和事故复盘。
